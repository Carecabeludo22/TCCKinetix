Annotations 
No Spring é comum adicionarmos anotações (annotations) em classes, 
atributos e métodos.  
Uma annotation é uma forma de adicionar informações (metadados) ao seu 
código que podem  ser interpretadas pelo compilador ou em tempo de 
execução por ferramentas e frameworks como o Spring. 
Uma annotation é uma palavra iniciada com '@' que você coloca acima de 
uma classe, método, atributo ou parâmetro, para dar instruções extras ao Java 
ou a algum framework sobre como aquele elemento deve ser tratado.

O que é JPA e por que usar com Spring Boot? 
O JPA (Java Persistence API) é uma especificação para mapeamento objeto-
relacional (ORM) em Java. Ele permite manipular dados no banco como objetos 
Java, facilitando operações como salvar, atualizar e buscar registros. 
Já o Spring Boot é um framework que simplifica a criação de aplicações 
Spring, com jpa, oferecem uma solução robusta, padronizada e com mínima 
configuração para acesso a dados

Model Services 
O que é Service Layer? 
O Service Layer, ou Camada de Serviço, é um padrão arquitetural que atua como intermediário 
entre a interface do usuário e a lógica de negócios de uma aplicação. Ele encapsula a lógica de 
negócios e fornece uma interface para que diferentes partes do sistema possam interagir de forma 
organizada e eficiente. Essa abordagem é especialmente útil em  aplicações web, onde a 
separação de responsabilidades é crucial para a manutenção e escalabilidade do código. 
 
Funções principais do Service Layer 
Uma das principais funções do Service Layer é a centralização da lógica de negócios. Ao invés de 
espalhar essa lógica por diferentes partes da aplicação, o Service Layer permite que ela seja gerida 
em um único local. Isso não apenas facilita a manutenção, mas também melhora a testabilidade 
do código, uma vez que as regras de negócio podem ser testadas independentemente da interface 
do usuário. Além disso, o Service Layer pode atuar como um ponto de controle para a validação de 
dados, garantindo que apenas informações válidas sejam processadas. 
 
Vantagens do uso do Service Layer 
O uso do Service Layer traz diversas vantagens, como a promoção de um design mais limpo e 
organizado. Isso é especialmente importante em projetos de grande escala, onde a complexidade 
pode aumentar rapidamente. Outro benefício é a possibilidade de reutilização de código. Com a 
lógica de negócios centralizada, diferentes partes da aplicação podem reutilizar os mesmos 
serviços, evitando duplicação e facilitando a manutenção. Além disso, o Service Layer pode 
facilitar a integração com outros sistemas, já que ele pode expor APIs que podem ser consumidas 
por diferentes clientes.

Na continuação, precisamos entender o conceito de “Injeção de Dependência” 
 
A injeção de dependência é um padrão de projeto utilizado para diminuir o acoplamento entre as 
classes de um sistema. Em outras palavras, é uma forma de estruturar o código para que as 
classes dependam de abstrações, em vez de dependerem diretamente de outras classes 
concretas. 
Mas o que isso significa na prática? Vamos supor que você esteja desenvolvendo um aplicativo que 
precisa se conectar a um banco de dados. Em vez de criar uma classe que faça a conexão 
diretamente, você cria uma interface que define os métodos que essa classe deve ter, como 
"conectar", "desconectar" e "executar consulta". 
Em seguida, você implementa uma classe concreta que implementa essa interface e realiza a 
conexão com um banco de dados específico, como o MySQL. Agora, ao invés de outras classes do 
Prof. Rogério Caetano 
55 
 
seu sistema dependerem diretamente da classe de conexão com o MySQL, elas dependem da 
interface genérica que você definiu. 
E é aí que a injeção de dependência entra em ação. Em vez de instanciar diretamente a classe de 
conexão dentro das classes dependentes, você assegura que essa dependência seja "injetada" por 
meio de construtores, métodos ou até mesmo configurações externas.

CORS 
CORS - Cross-Origin Resource Sharing (Compartilhamento de recursos com origens 
diferentes) é um mecanismo que usa cabeçalhos adicionais HTTP para informar a um 
navegador que permita que um aplicativo Web seja executado em uma origem (domínio) com 
permissão para acessar recursos selecionados de um servidor em uma origem distinta. Um 
aplicativo Web executa uma requisição cross-origin HTTP ao solicitar um recurso que tenha 
uma origem diferente (domínio, protocolo e porta) da sua própria origem.
